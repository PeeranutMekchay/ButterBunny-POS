# Butter Bunny POS · บัตเตอร์บันนี่

ระบบขายหน้าร้านสำหรับคาเฟ่และเบเกอรี่ ครบทั้ง 3 ส่วน

| ส่วน | ใช้อะไร | หน้าที่ |
|---|---|---|
| Frontend | HTML + CSS + JavaScript (`public/index.html`) | หน้าจอขาย ออเดอร์ เมนู โปรโมชั่น สมาชิก ของรางวัล รายงาน |
| Backend | Node.js + Express (`server/`) | REST API, ล็อกอินพนักงาน, คำนวณราคาและโปรโมชั่นซ้ำที่เซิร์ฟเวอร์, บันทึกบิลแบบ transaction, อัปเดตสดทุกเครื่องผ่าน Server-Sent Events |
| Database | SQLite (`data/butterbunny.db`) | เก็บข้อมูลทั้งหมดเป็นไฟล์เดียว ไม่ต้องติดตั้งโปรแกรมฐานข้อมูลแยก |

หลังติดตั้งครั้งแรกแล้ว ระบบทำงานได้โดยไม่ต้องต่ออินเทอร์เน็ต เพราะฟอนต์ ไลบรารี PDF และ QR ถูกเสิร์ฟจากเซิร์ฟเวอร์ในร้านเอง

## เริ่มใช้งาน

### 1. ติดตั้ง Node.js

ดาวน์โหลด Node.js เวอร์ชัน **LTS** (22.13 ขึ้นไป) จาก https://nodejs.org แล้วติดตั้งตามปกติ

### 2. เปิดเซิร์ฟเวอร์

**Windows แบบง่าย:** ดับเบิลคลิก `start-pos.bat` ครั้งแรกจะติดตั้งส่วนประกอบให้เอง แล้วเปิดเบราว์เซอร์ไปที่หน้า POS

**หรือพิมพ์คำสั่งเอง** (Windows, macOS, Linux):

```bash
npm install
```

```bash
npm start
```

แล้วเปิด http://localhost:3000

### 3. ตั้งค่าร้าน

1. ครั้งแรกจะเจอหน้า **ตั้งค่าร้านครั้งแรก** ใส่ชื่อผู้จัดการและ PIN 4 หลัก
2. ไปหน้า **ร้านค้า** ใส่เบอร์พร้อมเพย์ ที่อยู่ เบอร์โทร เลขผู้เสียภาษี และเพิ่มพนักงาน
3. ปรับราคาและสต็อกให้ตรงกับร้านในหน้า **เมนู**

ครั้งแรกที่เปิด ระบบจะใส่เมนูตัวอย่าง 32 รายการพร้อมรูป โปรโมชั่น 4 โปร และของรางวัล 8 ชิ้นให้อัตโนมัติ (จาก `seed/starter-data.json`)

### ใช้หลายเครื่องในร้าน

ตอนเปิดเซิร์ฟเวอร์ หน้าจอจะแสดงที่อยู่สำหรับเครื่องอื่น เช่น `http://192.168.1.20:3000` แท็บเล็ตหรือมือถือที่ต่อ Wi-Fi เดียวกันเปิดที่อยู่นั้นได้เลย ทุกเครื่องเห็นบิล สต็อก และแต้มเดียวกันแบบสด

ถ้าเครื่องอื่นเข้าไม่ได้ ให้อนุญาต Node.js ใน Windows Firewall (Windows จะถามตอนเปิดเซิร์ฟเวอร์ครั้งแรก ให้เลือก Private network)

## ฟีเจอร์

- **ขายหน้าร้าน:** เมนูมีรูป เลือกร้อน/เย็น/ปั่นและระดับความหวาน ทานที่ร้านหรือกลับบ้าน ออกเลขคิวต่อวันอัตโนมัติ
- **ชำระเงิน:** เงินสดพร้อมคำนวณเงินทอน, QR พร้อมเพย์ตามมาตรฐาน EMVCo พร้อมยอดเงิน, บัตร (บันทึกเลขอนุมัติจากเครื่อง EDC)
- **QR ยืนยันอัตโนมัติ:** ถ้าเชื่อม Opn Payments (เดิมชื่อ Omise) พอลูกค้าโอนแล้ว จอจะขึ้น "ชำระเงินสำเร็จ" และออกใบเสร็จเอง ไม่ต้องกดยืนยัน มีโหมดทดลองให้ลองก่อนสมัคร
- **เค้กปอนด์:** ตั้งราคาต่อปอนด์ได้ (ค่าเริ่มต้นปอนด์ละ 250 บาท) มีเมนูเค้กปอนด์ 3 รส และปุ่ม "ตั้งเป็นเค้กปอนด์" ในหน้าแก้เมนู
- **ใบเสร็จ:** ใบกำกับภาษีอย่างย่อพร้อม VAT 7% ดาวน์โหลดเป็น PDF ขนาด 80 มม.
- **ออเดอร์:** บอร์ดคิว กำลังทำ → พร้อมเสิร์ฟ → เสร็จแล้ว ยกเลิกบิลพร้อมคืนสต็อก คืนแต้ม และคืนของรางวัลเข้าตู้
- **เมนูและสต็อก:** เพิ่ม/แก้ไข/ลบเมนู อัปโหลดรูปเก็บบนเซิร์ฟเวอร์ ตัวเลือกพร้อมราคาบวกเพิ่ม และเติมสต็อก
- **โปรโมชั่น:** ลด %, ลดบาทต่อชิ้น, ซื้อ X แถม Y, ยอดครบลด กำหนดวัน ช่วงเวลา วันเริ่ม–สิ้นสุด และโค้ดคูปองได้
- **สมาชิก:** ค้นด้วยเบอร์โทร สะสมแต้ม มี 3 ระดับ และมีประวัติการเปลี่ยนแปลงแต้มทุกครั้ง (point ledger)
- **ตู้ของรางวัล:** แลกแต้มเป็นเมนูฟรี ของที่ระลึก หรือคูปองส่วนลด ทั้งในบิลและที่เคาน์เตอร์ ยกเลิกได้
- **รายงาน:** วันนี้ / เมื่อวาน / 7 วัน / เดือนนี้ / กำหนดเอง (สูงสุด 1 ปี) ดาวน์โหลด PDF ขนาด A4 และ CSV
- **พนักงาน:** เข้ากะด้วย PIN มีตำแหน่งผู้จัดการและแคชเชียร์ ล็อกหน้าจอเองเมื่อไม่ใช้งาน 20 นาที
- **จอเรียกคิวสำหรับลูกค้า** (`/queue`): เปิดบนทีวีหรือแท็บเล็ตหันหาลูกค้า แสดง "กำลังเตรียม" กับ "พร้อมรับแล้ว" ตัวเลขใหญ่ มีกระต่ายตัวใหญ่ขยับได้ ดีใจเมื่อมีคิวเสร็จ มีเสียงกริ๊ง และพูดว่า "ออเดอร์ที่ ศูนย์ ศูนย์ หนึ่ง ทำเสร็จแล้ว เชิญรับได้เลยค่ะ" (เลือกเสียงและความเร็วได้ เปิดด้วย Microsoft Edge บน Windows จะได้เสียงไทยแบบธรรมชาติ) ไม่แสดงชื่อหรือยอดเงินของลูกค้า
- **ออเดอร์ล่วงหน้า:** เลือกได้ 3 แบบ คือ เค้กปอนด์ (คิดราคาตามจำนวนปอนด์ให้เอง), เมนูหน้าร้าน (ดึงราคาจากเมนู) หรือสั่งพิเศษ (ตั้งราคาเอง) รับสั่งเค้กพร้อมข้อความบนเค้ก วันและเวลารับ รับมัดจำ (เงินสด/พร้อมเพย์/บัตร) เก็บส่วนที่เหลือตอนรับของพร้อมเงินทอน ยกเลิกแบบคืนหรือไม่คืนมัดจำ ปฏิทิน 14 วัน และใบรับออเดอร์ PDF
- **กะและลิ้นชักเงิน:** ต้องเปิดกะพร้อมเงินทอนตั้งต้นก่อนขาย บันทึกเงินเข้า-ออก (เช่น ซื้อน้ำแข็ง) ปิดกะด้วยการนับแบงก์และเหรียญ ระบบเทียบกับเงินที่ควรมีและแสดงส่วนต่าง มีประวัติกะและสรุปกะ PDF
- **ของเหลือและแผนอบ:** บันทึกขนมที่ทิ้งตอนปิดร้าน (ตัดสต็อกและเก็บมูลค่า) และแนะนำจำนวนที่ควรอบพรุ่งนี้จากยอดขายวันเดียวกันใน 4 สัปดาห์ก่อน หักของที่มักเหลือ และของที่ยังอยู่บนชั้น พิมพ์แผนอบเป็น PDF ได้
- **ร้านเปิดเลยเที่ยงคืนได้:** ตั้งเวลาเริ่มวันใหม่ได้ถึง 06:00 น. และออเดอร์ที่ยังไม่เสร็จจากเมื่อวานยังอยู่บนบอร์ดจนกว่าจะกดเสร็จ
- **วันเกิดสมาชิก:** ได้แต้มคูณ (ค่าเริ่มต้น x2) ตลอดเดือนเกิด และมีป้าย "เดือนเกิด" ขึ้นตอนเลือกสมาชิก
- **โปรใกล้ปิดร้าน:** หน้าขายแสดงแถบนับถอยหลังของโปรที่มีช่วงเวลา และมีปุ่มสร้างโปร "หลัง 19:00 ขนมอบลด 30%" ให้ในคลิกเดียว
- **ภาพรวมร้าน (เจ้าของ):** ยอดขายวันนี้เทียบเมื่อวานและสัปดาห์ก่อน กราฟรายชั่วโมง เมนูขายดี เงินในลิ้นชัก ออเดอร์ล่วงหน้าที่ต้องส่ง สต็อกใกล้หมด และของเสียเมื่อวาน
- **สำรองข้อมูลอัตโนมัติ:** ทุกคืนตอนตี 3 และตอนเปิดเซิร์ฟเวอร์ถ้าเกิน 1 วัน เก็บย้อนหลัง 30 ชุด ดาวน์โหลดไฟล์สำรองได้จากหน้าร้านค้า
- **แจ้งเตือนผ่าน LINE:** สรุปยอดตอนปิดกะ สต็อกใกล้หมด ออเดอร์ล่วงหน้าที่ต้องรับพรุ่งนี้ และกรณีสำรองข้อมูลไม่สำเร็จ

## ความปลอดภัยและความถูกต้องของข้อมูล

- **ราคาคิดที่เซิร์ฟเวอร์เสมอ:** หน้าจอส่งแค่รายการสินค้า เซิร์ฟเวอร์คำนวณราคาและโปรโมชั่นใหม่ด้วยโค้ดชุดเดียวกัน (`shared/pricing.js`) ถ้ายอดไม่ตรงกับที่หน้าจอแสดง (เช่น เพิ่งมีคนแก้ราคา) จะไม่บันทึก และให้ตรวจบิลใหม่
- **บันทึกบิลเป็น transaction เดียว:** บิล รายการสินค้า การตัดสต็อก แต้มสมาชิก และประวัติการแลกของรางวัล บันทึกพร้อมกันทั้งหมด หรือไม่บันทึกเลยถ้ามีอะไรผิด สต็อกไม่พอหรือแต้มไม่พอจะถูกปฏิเสธ
- **PIN ไม่ถูกเก็บเป็นตัวเลขตรง ๆ:** เก็บเป็น hash แบบ scrypt พร้อม salt ใส่ผิด 5 ครั้งล็อก 30 วินาที session หมดอายุเมื่อไม่ใช้งาน 12 ชั่วโมง
- **ตรวจสิทธิ์ทุก API:** แคชเชียร์ขาย จัดการคิว สมัครสมาชิก และแลกของรางวัลได้ ส่วนการแก้เมนู ราคา โปร ของรางวัล ข้อมูลร้าน พนักงาน การยกเลิกบิล การแก้แต้ม และการดูรายงาน ต้องเป็นผู้จัดการ
- **ตรวจข้อมูลที่ส่งเข้ามาทุกครั้ง:** ทั้งชนิด ความยาว และช่วงค่า รูปที่อัปโหลดต้องเป็น JPG/PNG/WebP ขนาดไม่เกิน 5 MB

```

server/index.js              จุดเริ่มเซิร์ฟเวอร์
server/app.js                เส้นทาง API, สิทธิ์, อัปโหลดรูป, Server-Sent Events
server/services.js           ขาย, ยกเลิกบิล, แลก/ยกเลิกการแลกของรางวัล (transaction)
server/repo.js               อ่าน/เขียนข้อมูลและตรวจความถูกต้อง

server/schema.sql            โครงสร้างตาราง SQLite
server/seed.js               โหลดข้อมูลเริ่มต้น
seed/starter-data.json       เมนู สต็อก โปร ของรางวัล ข้อมูลร้านเริ่มต้น
tests/api.test.js            ทดสอบ API (npm test)
tests/e2e.js                 ทดสอบผ่านเบราว์เซอร์ (npm run e2e, ต้องมี Playwright)
tools/illustrations/         สคริปต์ที่ใช้วาดรูปเมนู
start-pos.bat                ดับเบิลคลิกเพื่อเปิดระบบบน Windows
data/                        ฐานข้อมูลและรูปที่อัปโหลด (สร้างอัตโนมัติ ไม่ถูกเก็บใน Git)
```

## ฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `staff`, `sessions` | พนักงาน (PIN เป็น hash) และการเข้าสู่ระบบ |
| `config` | ข้อมูลร้าน พร้อมเพย์ VAT อัตราแต้ม |
| `menu`, `stock` | เมนูและจำนวนคงเหลือ (`stock.id` เป็นรหัสเมนู หรือ `rw-<รหัสของรางวัล>`) |
| `promos` | โปรโมชั่นและเงื่อนไข |
| `rewards` | ของรางวัลในตู้ |
| `members`, `point_ledger` | สมาชิก และประวัติแต้มเข้า-ออกทุกครั้ง |
| `orders`, `order_items` | บิลและรายการในบิล (เลขคิวไม่ซ้ำกันในแต่ละวัน) |
| `redeems` | ประวัติการแลกของรางวัล |
| `shifts`, `cash_moves` | กะ เงินทอนตั้งต้น เงินที่นับได้ และเงินเข้า-ออกลิ้นชัก (เปิดได้ทีละ 1 กะ) |
| `preorders`, `preorder_payments` | ออเดอร์ล่วงหน้า และเงินมัดจำ/ส่วนที่เหลือ/เงินคืน |
| `waste` | ขนมที่ทิ้งตอนปิดร้าน |

**สำรองข้อมูล:** ระบบสำรองให้เองที่ `data/backups/` (เก็บ 30 ชุดล่าสุด) ควรคัดลอกไฟล์ในนั้นไปเก็บนอกเครื่องเป็นระยะ เช่น USB หรือ Google Drive ส่วนรูปที่อัปโหลดอยู่ใน `data/uploads/`

**กู้คืนจากไฟล์สำรอง:** ปิดเซิร์ฟเวอร์ แล้วลบ `data/butterbunny.db`, `data/butterbunny.db-wal` และ `data/butterbunny.db-shm` จากนั้นคัดลอกไฟล์สำรองที่ต้องการมาวางแทนในชื่อ `data/butterbunny.db` แล้วเปิดเซิร์ฟเวอร์ใหม่

ฐานข้อมูลเดิมจากเวอร์ชันก่อนอัปเกรดได้เอง ตารางและคอลัมน์ใหม่จะถูกเพิ่มตอนเปิดเซิร์ฟเวอร์ ข้อมูลเดิมไม่หาย

**ตั้งค่าผ่าน environment variable:**

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตของเซิร์ฟเวอร์ |
| `HOST` | `0.0.0.0` | ตั้งเป็น `127.0.0.1` ถ้าจะให้ใช้ได้เฉพาะเครื่องนี้ |
| `DATA_DIR` | `./data` | โฟลเดอร์เก็บฐานข้อมูลและรูป |
| `BACKUP_HOUR` | `3` | ชั่วโมงที่สำรองข้อมูลทุกคืน (0–23) |

วันที่ของบิลใช้เวลาของเครื่องที่รันเซิร์ฟเวอร์ ควรตั้งเวลาเครื่องเป็นเขตเวลาประเทศไทย

## ตั้งค่ารับเงิน QR แบบยืนยันอัตโนมัติ

QR พร้อมเพย์ธรรมดา (โอนเข้าบัญชีร้านตรง ๆ) ไม่มีช่องทางแจ้งร้านเมื่อเงินเข้า ถ้าอยากให้ระบบรู้เองว่าเงินเข้าแล้ว ต้องรับเงินผ่านผู้ให้บริการรับชำระเงิน ระบบนี้รองรับ [Opn Payments](https://docs.opn.ooo/promptpay)

1. สมัครบัญชีร้านค้าที่ Opn Payments และยืนยันตัวตนร้าน
2. ส่งอีเมลถึง Opn ขอเปิดใช้ PromptPay
3. คัดลอก Secret key (`skey_...`) จากหน้า Keys ใน Dashboard ใช้ `skey_test_...` ทดสอบก่อนได้
4. ในหน้า **ร้านค้า** ส่วน "รับเงิน QR แบบยืนยันอัตโนมัติ" เลือก Opn Payments ใส่ key แล้วกดบันทึก

ทุกบิลที่ลูกค้าเลือกจ่ายด้วยพร้อมเพย์ ระบบจะสร้าง QR ใหม่ผ่าน Opn แล้วเช็กสถานะทุก 2–3 วินาที พอ Opn แจ้งว่าได้รับเงินแล้ว จอจะขึ้น "ชำระเงินสำเร็จ" และออกใบเสร็จเอง เซิร์ฟเวอร์ตรวจซ้ำอีกชั้นว่ายอดที่ได้รับตรงกับบิล และ QR หนึ่งอันใช้ได้กับบิลเดียว

- Opn คิดค่าธรรมเนียมต่อรายการตามสัญญาของแต่ละร้าน และโอนเงินเข้าบัญชีร้านตามรอบของ Opn ไม่ได้เข้าทันทีแบบพร้อมเพย์ตรง
- เครื่องที่รันเซิร์ฟเวอร์ต้องต่ออินเทอร์เน็ต ถ้าเน็ตหลุด ยังกด "ยืนยันเอง" ได้
- **โหมดทดลอง** ใช้ลองดูขั้นตอนโดยไม่มีเงินเข้าจริง ผู้จัดการกด "จำลองว่าลูกค้าโอนแล้ว" แทนการโอน

## ตั้งค่าแจ้งเตือน LINE

LINE Notify ปิดบริการไปแล้วตั้งแต่ 31 มี.ค. 2025 ระบบนี้จึงส่งผ่าน **LINE Messaging API** ของ LINE Official Account

1. สร้าง LINE Official Account ของร้าน แล้วเปิดใช้ Messaging API ที่ https://developers.line.biz/console/
2. ในแท็บ Messaging API กด Issue **Channel access token (long-lived)**
3. คัดลอก **Your user ID** (ขึ้นต้นด้วย U) จากแท็บ Basic settings ถ้าจะส่งเข้ากลุ่ม ให้เชิญบัญชีร้านเข้ากลุ่มแล้วใช้ Group ID แทน
4. ให้เจ้าของเพิ่มบัญชีร้านเป็นเพื่อนใน LINE
5. ในหน้า **ร้านค้า** ของ POS ใส่ token กับ ID แล้วติ๊ก เปิดใช้ จากนั้นกด **ส่งข้อความทดสอบ**

ข้อความแบบ push นับรวมในโควตาข้อความของ LINE Official Account ถ้าใช้แพ็กเกจฟรี ควรตรวจโควตาต่อเดือนก่อน

เครื่องที่รันเซิร์ฟเวอร์ต้องต่ออินเทอร์เน็ตจึงจะส่ง LINE ได้ ส่วนการขายยังทำงานได้ตามปกติแม้ไม่มีอินเทอร์เน็ต

## ทดสอบ

```bash
npm test
```

ทดสอบ API 21 ชุดบนฐานข้อมูลในหน่วยความจำ ครอบคลุม:
- การตั้งค่าครั้งแรกและการล็อกเมื่อใส่ PIN ผิด
- สิทธิ์ของผู้จัดการกับแคชเชียร์
- การคำนวณโปรโมชั่น และการปฏิเสธเมื่อยอดไม่ตรง เงินไม่พอ หรือสต็อกไม่พอ
- แต้มสมาชิก การแลกของรางวัล การยกเลิกบิลที่คืนทุกอย่างครบ
- การตรวจข้อมูลที่ส่งเข้ามา
- กะและส่วนต่างเงินในลิ้นชัก ออเดอร์ล่วงหน้า (มัดจำ รับของ ยกเลิก) ของทิ้งและแผนอบ จอเรียกคิว ภาพรวมร้าน วันเกิดสมาชิก การนับวันทำการ
- การสำรองข้อมูล และการส่ง LINE (ทดสอบกับเซิร์ฟเวอร์จำลอง)
- เค้กปอนด์ และ QR ยืนยันอัตโนมัติ ทั้งโหมดทดลองและ Opn Payments (ทดสอบกับเซิร์ฟเวอร์จำลอง)

ทดสอบผ่านเบราว์เซอร์ (เปิดเซิร์ฟเวอร์ไว้ก่อน และต้องติดตั้ง Playwright):

```bash
npm run e2e -- http://localhost:3000
```

ควรรันกับฐานข้อมูลเปล่าเท่านั้น ใช้ `DATA_DIR` ชี้ไปโฟลเดอร์ใหม่ เพราะชุดทดสอบนี้จะสร้างบิลและสมาชิกจริงลงในฐานข้อมูล

## ข้อจำกัด

- ระบบตรวจกับธนาคารไม่ได้ว่าเงินพร้อมเพย์เข้าแล้ว พนักงานต้องดูแจ้งเตือนในแอปธนาคารก่อนกดยืนยัน ส่วนบัตรต้องรูดที่เครื่อง EDC แยกต่างหาก ควรลองสแกน QR ยอด 1 บาทก่อนเปิดใช้จริง
- ใบเสร็จพิมพ์ผ่านไฟล์ PDF ยังไม่ได้ต่อเครื่องพิมพ์ใบเสร็จโดยตรง
- เซิร์ฟเวอร์ใช้ HTTP ภายในร้าน ถ้าจะเปิดให้เข้าจากอินเทอร์เน็ต ต้องมี HTTPS (เช่น วางหลัง reverse proxy) ก่อน
